## 一、三次真实运行结果

### 运行 1：写斐波那契函数（3 轮完成）

| 轮 | 动作 | 结果 |
|---|---|---|
| 1 | write_file(fib.py) | OK |
| 2 | run_python(fib.py) | OK（exit 0） |
| 3 | final | "验证了 fib(10)==55" |

**踩坑点 ①「幻觉式汇报」**：模型写的 `fib.py` 里**只有函数定义、没有 print 验证**，`run_python` 输出其实是空的，但模型在 final 里**声称「验证了 fib(10)==55」**——它没有真验证，是"脑补"了一个结果。

> **我的修复**：在 system prompt 加约束——「只有当 run_python 的观察里明确打印出数值，才能在 final 引用；否则只能陈述你实际做了什么」。**重跑后模型改口**：诚实说「运行结果未直接输出，但可以确认 fib(10)=55」，不再谎称"已验证"。这是一个可复现的「发现问题→约束→改善」闭环。
> 附带观察：改进后模型多了一步 `list_files`（先探查 workspace 再动手），行为更谨慎。

### 运行 2：修复减法 bug（4 轮，完美自愈）

| 轮 | 动作 | 结果 |
|---|---|---|
| 1 | read_file(buggy.py) | OK（看到 `return a - b`） |
| 2 | edit_file(`a - b`→`a + b`) | OK |
| 3 | run_python | OK，输出 `8` |
| 4 | final | "返回了预期结果 8" |

**亮点**：模型先 read_file 定位 → edit_file 精准替换 → run_python 验证输出 8 → final，是一条**有依据的自愈闭环**（先看清楚再改，改完真跑验证）。

### 运行 3：修复除零错误（4 轮，全自主自愈，最漂亮）

| 轮 | 动作 | 结果 |
|---|---|---|
| 1 | run_python(div.py) | **FAIL**（ZeroDivisionError） |
| 2 | edit_file（加 `if b==0` 防御） | OK |
| 3 | run_python | OK，输出"除数不能为零" |
| 4 | final | "解决了 ZeroDivisionError" |

**亮点**：这次我**没有告诉模型 bug 在哪**，只说"运行 div.py，报错就修"。模型完全自主地：
1. 先跑 → 拿到 stderr 里的 ZeroDivisionError；
2. 自己诊断「除数为零」；
3. 主动加 `if b == 0` 的防御分支；
4. 再跑成功。

**这就是「多轮自愈调试」的真实证据**：报错的 stderr 原样喂回模型，模型据此生成修复动作，形成闭环。

## 二、关键观察结论（面试能直接讲）

1. **自愈闭环是真的能跑通的**，且模型能自主诊断「运行时错误」并修复（运行 3），不需要人提前指出 bug。
2. **模型会「幻觉式汇报」**（运行 1）——声称验证了但实际没验证。这是我设计里需要加强的边界：不能只信模型的 final 陈述，要信工具的**实际 stdout**。
3. **JSON 约束在 Qwen2.5-7B 上基本遵守**（三轮都稳定输出合法 JSON，未见明显杂讯），但这是 3 次小样本，不能下结论——样本量需要扩大才敢说「格式遵守率」。

## 四、诚实边界

- 当前只做了 **3 次真实运行**，结论是**观察性**的，不是统计结论（样本太小）。
- 模型是 **7B 免费小模型**，行为不代表更大模型（GPT-4 / DeepSeek-V3 等）；换大模型「幻觉率」「格式遵守率」会不同，这是可讲的边界。
- 自愈目前只能修**语法/运行时错误**（如除零、符号写反），**修不了逻辑错误**（如业务意图理解错）——这是 Coding Agent 的通用局限，我明确承认。
